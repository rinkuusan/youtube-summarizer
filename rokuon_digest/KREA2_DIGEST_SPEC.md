# digest.json 仕様と Krea2Bridge への組み込み方

## 目的
自宅の録音文字起こしログから `digest.json` を作り、チャットキャラクター「ボタミ」が
「純が最近何をしていたか」「いつ頃活動しているか」を把握できるようにする。
PC側（Krea2Bridge: C# .NET の HTTP サーバー。Android チャットアプリ Botagram 用のプロンプトを組み立てる）
の担当者はこの文書を元に統合する。キャラクターは成人女性という設定で変更なし。

生成: `python -m rokuon_digest LOG.txt -o digest.json [--no-llm] [--days N]`
（要約には環境変数 `GROQ_API_KEY` または `--api-key`。`--no-llm` なら summary は null）

完全ローカルで要約する場合（Ollama の OpenAI 互換API。キー不要）:
`LLM_BASE_URL=http://localhost:11434/v1 SUMMARY_MODEL=<ollamaのモデル名> python -m rokuon_digest LOG.txt -o digest.json`
（`LLM_BASE_URL` 未設定なら Groq。Groq 以外の URL ではキーなしで動く）

## フィールド
```json
{"generated_at": "ISO8601", "source": "元ファイル名",
 "notify_windows": [{"start":"13:00","end":"14:00","score":0.83}],
 "days": [{"date":"2026-10-14","weekday":"水","jun_active":[{"start":"08:00","end":"09:30"}],
           "hist30":{"08:00":3},"counts":{"純":20,"あやか":15,"その他":13,"テレビ・動画":26,"low_conf":26},
           "watched":["04:01 ..."],
           "summary":{"jun_did":[],"jun_mood":"","with_ayaka":[],"topics":[],"uncertain":[]}}]}
```
- `generated_at` / `source`: 生成時刻とログのファイル名。古いデータかどうかの判断に使う。
- `notify_windows`: 純が発話した日の割合（score = 発話のあった日数 / 全日数）が高い1時間枠の上位3つ（重複なし）。
- `days`: 日付の降順（先頭が最新）。
  - `jun_active`: 純が活動していた時間帯（30分バケットを間隔60分以内で結合。end は最後のバケット開始+30分）。
  - `hist30`: 30分バケットごとの純の発話ブロック数。
  - `counts`: 生ログのブロック数（幻聴フィルタ前）。`その他` は人物NN・不明。`low_conf` は ⚠ 付きの数。
  - `watched`: テレビ・動画の視聴メモ（時刻と冒頭約60字。純が見ていた内容の目安）。
  - `summary`: LLM要約。`jun_did`（純がしたこと）、`jun_mood`（様子）、`with_ayaka`（あやかとのこと）、
    `topics`（話題）、`uncertain`（不確かな事項）。`--no-llm` や失敗時は `null`。

## プロンプトへの注入
最新1〜2日の summary から、約600字以内の短いブロックを作り、system/コンテキストに追加する。例:

```
【ボタミが知ってる純の最近】
10/14(水): 午前は動画を見て過ごし、昼に買い物へ。夜はあやかと夕食。様子: 落ち着いている。
10/13(火): 仕事の資料づくり。話題: 引っ越し、旅行。
※断定してよいのは上記のみ。「確認したいこと」は事実として話さず、聞くだけにする。
確認したいこと: 夜に誰かと電話していた？
```
- 古い日（3日以上前）は入れないか、さらに短くする。`generated_at` が古い場合は「最近」と言わない。
- `summary` が null の日は、`jun_active` と `watched` から「この時間帯に起きていたらしい」程度に留める。

## uncertain の扱い
`uncertain` の項目は事実としてキャラクターに言わせてはならない。質問（「〜だった？」）としてのみ使ってよい。
`low_conf`（⚠）が多い日は話者の取り違えが多いので、さらに慎重にする。

## 通知タイミング
`notify_windows` をキャラクター発の通知（話しかけ）のスケジュールに使う。
純が活動している可能性が高い枠内で、1日あたりの回数と最小間隔はPC側で制限する。
`jun_active` で当日すでに活動が見えていれば、その時間帯を優先してもよい。

## データの受け渡し
手動でファイルをコピーするか、PC側から取りに行く（pull）方式にする。
PCをインターネットに公開してはならない。録音ログと digest.json は私的な内容なのでリポジトリにコミットしない
（`.gitignore` に `*rokuon*.txt` / `digest*.json` を追加済み）。

## 未検証の前提
- `[H:MM]` は時計の時刻（ローカル時間）として扱っている。録音開始からの経過時間ではない前提。
- `⚠` は話者判定の信頼度が低いという意味として扱っている。
- テレビ・動画の音声や人物NNの発話は純の行動とは限らない。
- 幻聴（Whisperの定型句）の除去リストは暫定で、ログを見て調整が必要。
